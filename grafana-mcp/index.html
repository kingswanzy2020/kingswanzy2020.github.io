Case study — Observability / AI

Grafana dashboards built and updated through MCP

I connected an AI agent in Cursor to Grafana and PostgreSQL through MCP servers, then built a six-panel e-commerce dashboard by describing it — and changed the data underneath to watch the panels re-rank live.

Local stack

Grafana and PostgreSQL ran in Docker on my machine, driven from Cursor. Nothing was hosted. The schema and seed data in the repo reproduce the database; everything below describes that local session.

What it does

Summary

Cursor's mcp.json defines a Grafana MCP server (stdio transport, the Grafana URL and a service-account token) alongside Docker and PostgreSQL servers, which gives the agent hands on each tool. I added PostgreSQL as a Grafana data source at host.docker.internal:5432, then asked for a dashboard: four KPI tiles — total revenue, order count, average order value, customers — bars for orders by status and revenue by region, and a monthly revenue trend. A second dashboard put a panel over the raw customer table next to panels over a pre-aggregated table, and I changed the data to watch them update.

How it is wired

The mechanism

Why MCP instead of clicking through Grafana? Without it, a dashboard means logging in, writing SQL per panel and fiddling with visualisation settings — enough friction that dashboards don't get built. The MCP server turns a described panel into Grafana API calls, authenticated with a service-account token rather than my login.

Why pre-aggregated tables? A panel over the raw table re-scans every customer row on every refresh, which gets slower as data grows. Panels over a materialised, dbt-style aggregate read a handful of pre-computed rows. Putting both side by side made the trade-off visible.

Why host.docker.internal? Grafana runs in a container; PostgreSQL was published on the host. That name resolves to the host from inside the container.

What I verified, and how

Evidence, separated from design intent

Building something and being able to prove it works are different claims, so I've kept them separate below. Measured means I created the condition myself and recorded what happened. Observed means I looked at the dashboards and saw the state it was already in. By design means the configuration guarantees it, but I didn't run a test against it — better to say that plainly than dress it up as a result.

Measured

Changing the data re-ranked the panels live

Through the agent I updated the raw and aggregated tables. On refresh, the raw-data panel showed Egypt's count up, the top-country panel switched from Korea to Egypt, and total customers stayed at 2K — each panel following the table it reads.

Method Updated the data through the Postgres MCP server and refreshed the pipeline dashboard.

Observed

A six-panel dashboard from a description

The E-Commerce Analytics dashboard came out with total revenue $5.09M, 10,000 orders, $509 average order value and 2,000 customers, plus orders by status, revenue by region, and a monthly revenue trend.

Method Read the dashboard in Grafana.

Observed

All three MCP servers connected

After a full restart, Cursor listed the Docker, Grafana and PostgreSQL servers with green indicators — 4, 50 and 9 tools — and the Grafana data source test reported Database Connection OK.

Method Checked Cursor's installed MCP servers and Grafana's data source test.

By design

Aggregated panels stay fast as data grows — not timed

The raw panel scans every row per refresh; the aggregated panels read pre-computed rows. On 2,000 customers both felt instant, so I'm stating the scaling property, not a measured difference.

Method Reviewed the panel queries. No timing captured.

Four claims. one measured, two observed, one stated as a design property rather than dressed up as a result.

What actually broke

One failure worth keeping

Wiring the MCP servers was the hard part

The dashboard was quick once the agent could reach Grafana. Getting there — the stdio transport, the URL, a service-account token, and a full Cursor restart before the servers showed green — took most of the ninety minutes.
