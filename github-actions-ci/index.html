Case study — CI/CD

CI fundamentals with GitHub Actions and pytest

I wrote a CI workflow from scratch that runs a pytest suite on every push and pull request to main, broke a test on purpose to prove it catches failures, and added a build step that turns each green run into an installable Python package.

CI workflow

This is a workflow in a repository, not a running service. It runs on GitHub's runners on every push and pull request to main. Everything below describes the runs from the build.

What it does

Summary

The project is a small Python module with typed functions. I added a multiply function and tests for it, grouped in pytest classes, and confirmed all six tests passed locally in a virtualenv. Then I wrote .github/workflows/ci.yml: checkout, set up Python 3.11, install requirements, run pytest -v. After that worked, I added python -m build and actions/upload-artifact, so every green run leaves a python-package artifact anyone can pip install.

How it is wired

The mechanism

Why run tests in CI when they pass locally? "Passes on my laptop" depends on my laptop. CI runs the same commands on a clean runner for every push and pull request, so a broken change is caught before anyone pulls it, not after.

Why break a test on purpose? A pipeline that has only ever been green hasn't proved anything. I changed an assertion so it was false and pushed: the run went red. Fixing it and watching it go green again is the evidence the workflow is actually checking something.

Why upload an artifact? Tests answer "does it work?"; the artifact answers "what do I ship?". python -m build produces a wheel and a source tarball, and uploading them as one artifact means each green commit has a package attached to it.

What I verified, and how

Evidence, separated from design intent

Building something and being able to prove it works are different claims, so I've kept them separate below. Measured means I created the condition myself and recorded what happened. Observed means I looked at the workflow runs and saw the state it was already in. By design means the configuration guarantees it, but I didn't run a test against it — better to say that plainly than dress it up as a result.

Measured

A false assertion turned the run red; fixing it turned it green

I introduced a failing assertion in the test file and pushed; CI failed. I corrected the assertion and pushed again: the run named Fix the test (#3) passed every step.

Method Pushed the broken test, then the fix, and read both runs in the Actions tab.

Observed

Six tests passed locally before CI existed

pytest -v collected six tests across three test classes, including the two for multiply, and passed all of them in 0.01 seconds.

Method Ran pytest -v in the virtualenv.

Observed

Every green run produced an installable package

Run #4, Add build and artifact upload to CI, succeeded in 21 seconds and attached one artifact, python-package, at 5.27 KB. I downloaded it from the run page.

Method Read the run summary and downloaded the artifact.
